# Nyulo Interior — Admin API

Node.js/Express API behind the admin panel. It signs admins in, stores uploaded photos, and edits everything the public website shows: projects, services, reviews, journal articles, site-wide content and leads.

It is a separate app from the public API (`../BackEnd`) and shares only the database with it.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5001/admin-api/v1
```

With `DATABASE_URL` unset it reads and writes the JSON files in `../BackEnd/data`, the same files the public API uses in development, so run the public API once first to create them. Set `DATABASE_URL` to the PostgreSQL connection string to use the real database.

The first time, open the admin panel: it asks you to create the admin account.

## Structure

```
src/
├── config/        # environment + PostgreSQL connection
├── repositories/  # Postgres and JSON-file adapters behind one interface
├── validations/   # registry of editable collections and their schemas
├── services/      # auth, generic collection CRUD, site settings, dashboard
├── controllers/   # thin HTTP handlers
├── routes/        # all routes, mounted at /admin-api/v1
├── middlewares/   # sign-in check, image upload, errors
└── utils/         # password hashing, tokens, validation, helpers
```

## API (`/admin-api/v1`)

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Status and storage mode |
| GET | `/auth/status` | Whether the first admin still has to be created |
| POST | `/auth/setup` | Create the first admin (refused once one exists) |
| POST | `/auth/login` | Sign in with username and password, returns a token |
| GET | `/auth/me` | Current admin |
| POST | `/auth/password` | Change password |
| GET | `/dashboard` | Counts and latest leads |
| POST | `/uploads` | Upload one image (`file` field), returns its public URL |
| GET | `/uploads/:file` | Serve an uploaded image |
| PUT / DELETE | `/settings/:section` | Save a site section / reset it to the default |
| GET / POST | `/resources/:name` | List / create |
| GET / PATCH / DELETE | `/resources/:name/:id` | Read / update / delete |

`:name` is one of `projects`, `services`, `testimonials`, `blogs`, `contacts`, `estimates`. Leads (`contacts`, `estimates`) cannot be created here and only their `status` and `notes` can change.

Everything except `/health`, `/auth/status`, `/auth/setup`, `/auth/login` and `GET /uploads/:file` requires `Authorization: Bearer <token>`.

## Security notes

- Passwords are stored as salted scrypt hashes, never in plain text. Minimum length is 10 characters.
- Sign-in, setup and password change are limited to 10 attempts per 15 minutes per address.
- Tokens are signed with `JWT_SECRET`, or with a secret generated on first run and kept in `data/jwt-secret`. They expire after 7 days.
- Uploads accept JPG, PNG, WebP, AVIF and GIF up to 8 MB. The saved file name and extension are generated by the server; SVG is refused because it can contain scripts.
- Image and link fields must start with `http(s)://` or `/`, so a `javascript:` address can never reach the public site.
- Request bodies are whitelisted against each collection's schema; unknown fields are dropped.
